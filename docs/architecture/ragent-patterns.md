# 架构模式迁移与工程对照 (ragent 经验吸收)

> **背景**：本项目在设计阶段参考了 `ragent` 仓库的核心设计思想，全面吸收其经过生产检验的 RAG 核心模式，舍弃其 Java/Spring 固有复杂度，以原生 Python 3.12 与 LangGraph 现代化技术栈重新实现。

---

## 核心模式迁移矩阵

| 原型设计模式 (ragent) | ClauseRAG 落地实现与工程演进 |
| :--- | :--- |
| **阶段化对话管道** | 基于 LangGraph 明确建模的有界状态图（最多 2 轮改写重试，严禁死循环）。 |
| **多通道检索引擎** | 统一的轻量级 Python Protocol，解耦 Dense 密集向量与 Keyword 倒排通道。 |
| **检索预算管理 (Budget)** | 单次请求全局受控的 Token 与候选配额（Top-K、融合上限、精排上限与上下文窗口上限）。 |
| **后处理器流水线** | 确定性处理链路：结果归一化 → 去重 → RRF 融合 → 二次重排 → 证据门控 → 父切片展开。 |
| **块感知分块 (Block-aware)** | 感知 Markdown 标题树、表格、段落与代码块边界的 Parent-Child 两级分块。 |
| **重排分数语义** | 隔离原始 RRF 融合分与 BGE-Reranker 注意力分，明确记录降级与不可用状态。 |
| **流式生命周期封装** | 严格的单一终态 SSE 事件流、首字延迟（TTFT）统计与客户端断开取消传播。 |
| **引用与证据拼装** | 请求局部短引用标记 `[Sn]`，由服务端强核验并解析行号与原文片段。 |
| **摄取流水线状态机** | 基于 PostgreSQL `ingestion_jobs` 表与不可变制品指引的状态持久化与租约认领。 |
| **外部供应商适配** | 基于 SiliconFlow 的标准 OpenAI 兼容适配器，带有界超时、错误分类与抖动退避。 |
| **全链路追踪增强** | Langfuse 深度集成，串联会话、任务、请求与模型耗时，严格脱敏合同全文。 |

---

## 首发版本显式裁剪（避免过度设计）

在初版中坚决不引入以下高成本低收益特性：
- 不引入复杂的动态可视化流水线编排器（拖拽式配置）；
- 不引入无界自我反思与复杂 Agent 工具集；
- 不引入外部 Web 动态爬虫；
- 不引入庞大的 Java/Spring 抽象层次。
以最短、最克制、最鲁棒的路径达成生产级核心闭环。
