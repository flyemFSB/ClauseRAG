## What the run found, and what was fixed at the root

The run was the first execution of the agent, observability, parsing, chunking and indexing lanes since
the P0–P4 refactor, and it found six defects. Each was fixed at its cause, not at the assertion:

1. **Valid citation markers were stripped from the answer (mine).** The sanitizer that removes protocol
   markers from untrusted document text had been reused for the answer, so `validate_answer` deleted
   *valid* `[S#]` markers too and the terminal answer no longer matched the streamed deltas
   (`answer_is_the_deltas` in the agent lane). Fixed by splitting the two regexes: the answer keeps its
   valid ids (invalid ones are handled by the policy), source text loses every marker (`domain/citation.py`).
2. **A provider-accepted OCR job that the provider fails was classified as deterministic (product).**
   The `state == "failed"` branch classified from the *envelope* code, which is always `0`/`Success`
   because it describes the query, not the job; the job-level reason lives in `data.errorMsg` (the
   official polling example reads exactly that field). Every such job was therefore written off as
   `parse_failed`/manual-retry. Now the job's own reason is recorded and the attempt is transient,
   bounded by the row's budget (`infrastructure/parsing/paddleocr_parser.py`); verified on a real
   provider failure (`paddleocr-vl job … failed at the provider: 系统错误-拆页`).
3. **The observability lane could only pass on a machine that already had Langfuse's bucket.**
   `cli observability-init` provisions Langfuse's own database and S3 bucket, but it ran only in
   standalone mode: `smoke.ps1` hands every lane `-EnvironmentReady` and never provisions that bucket,
   and the probe swallowed the CLI's exit code. Two fixes: the lane now provisions its own prerequisite
   in both modes and asserts the exit code (`scripts/probes/observability.ps1`, including the
   business bucket it also needs). Verified by deleting the `rag-langfuse` bucket and watching the lane
   recreate it.
4. **The cancellation check matched a renamed log event (probe).** It looked for the English
   `agent.run_finished`, which the logging refactor localised; it now matches the payload the runner
   writes (`logger` + `terminal`), and the run it hangs up on asks for a long answer so the client
   provably disappears while the model is still streaming (`scripts/probes/agent.ps1`).
5. **The chat wire contract called the wrong endpoint (probe).** It hard-coded SiliconFlow while `.env`
   points chat at SenseNova, and asked for `max_tokens: 64` from a model that spends tokens on
   reasoning (measured: 200 with `content=None`). It now resolves the endpoint exactly as `open_chat`
   does (`RAG_CHAT_BASE_URL`/`RAG_CHAT_API_KEY`, else SiliconFlow), uses generous budgets for the format
   checks, and retries 429/5xx. `response_format: json_schema` is measured and printed as **400 on
   SenseNova** — the product only ever sends `json_object`, which is honoured (200, parses).
6. **Three probe contracts had drifted from the implemented ones.** The parsing probe asserted a
   *stable artifact key* across a re-parse (a leftover of the pre-ADR-0030 single-key scheme); it now
   asserts the stronger pair the design actually promises — the recorded key holds the recorded
   checksum, and the object the row replaced is deleted — plus the attempt-scoped key shape. The queue
   probe's retry assertions were re-expressed on the job row (retry decisions with the attempt they
   spent, the dispatcher's own reconcile events, the measured gap between attempts) instead of the
   removed `SmartRetryMiddleware`'s log line. A shared `Invoke-StageUntilSettled` helper honours the
   retry contract for fixture parses that a probe drives through the CLI, so a transient provider
   failure is retried within the row's budget instead of failing the lane (and it fails when the budget
   is spent). `cli/errors.py` was deleted: the CLI's failure line recomputed the failure state from the
   error taxonomy — a second owner that could contradict the row — and now prints the classification
   and points at the job row.

Two fixtures were corrected for the same reason: the abstention question is now contract-shaped
(a general-knowledge question is routed to `direct_response` *by design*, per the classifier's prompt,
and that route takes no retrieval round), and the transient OCR sample gets a bounded re-ask.

## Gaps and residual risk

- **PaddleOCR-VL queue latency is outside our control.** Measured during this session: the provider's
  submission queue answered `10010` ("queue full, retry later") for ~45 minutes, and later accepted
  jobs that it left `pending` past our 300 s window (a job we abandoned at 300 s was completed by the
  provider 13 minutes later). The platform's response is the documented one: classified transient,
  retried within `RAG_JOB_MAX_ATTEMPTS`, then terminal with the provider's own message and the retry
  endpoint as the recovery path. The official API exposes no cancel/delete route (checked in the
  polling example), so a given-up job cannot be released early. A deployment that sees this often
  should raise `RAG_PADDLEOCR_POLL_TIMEOUT_SECONDS` and/or `RAG_JOB_MAX_ATTEMPTS`; the parsing lane
  fails loudly when the budget is spent (it did, three times, before the provider recovered).
- **Frontend:** the two files over the 500-line ceiling (`KnowledgeBaseOverview.tsx`,
  `RetrievalDebugPage.tsx`) are *not* split; the frontend is prototype-only and has no browser
  harness, so `pnpm check` + `pnpm test` (29 tests) are its evidence, not this suite.
- **Nothing else is unverified:** every lane above ran against real containers and real providers in
  this run, including the OCR-dependent ones.
